### fs-02 run 3: How does the Twitch client handle rate limits and failed requests?

Answer: In `Twitch.get`, the client retries requests up to 8 times:

- **Network exceptions (`RequestException`)**: Sleeps for an increasing duration (`min(60, 5 * (attempt + 1))` seconds) and retries.
- **401 Unauthorized**: Forces auth token refresh (`self._set_auth(force=True)`) and retries.
- **429 Rate Limit or >=500 Server Errors**: Extracts the `Ratelimit-Reset` timestamp header and sleeps until it passes before retrying.
- **Proactive Rate Limiting**: If `Ratelimit-Remaining` is less than 10, it sleeps until `Ratelimit-Reset` before returning the response.
- **Persistent failures**: If all 8 attempts fail, it raises a `RuntimeError`.

- [x] it retries up to 8 times
- [x] on 429 or a 5xx error it waits until the rate limit reset time
- [x] on 401 it refreshes the token

- [x] if filled goes above capacity it is rolled back

### fs-01 run 2: How is the fit score of a streamer computed and what are its parts?

Answer: The fit score (0-100) is computed by rounding the sum of five component scores:

1. Engagement: Up to 30 points, calculated as min(engagement_pct / 10, 1) * 30.
2. Consistency: Up to 20 points, calculated as min(days_seen_live / max(sweep_days, 1), 1) * 20.
3. Giveaway/Sponsor Signal: Up to 20 points (20 if giveaways and sponsor/brand signal are present, 15 if only giveaways, 10 if only sponsor/brand signal, 0 otherwise).
4. Location confidence: Up to 15 points (high: 15, medium: 11, low: 6, none: 0).
5. Audience size: Up to 15 points based on average viewers (15 if between 20 and 80 viewers, 10 if between VIEWERS_MIN and VIEWERS_MAX, 3 otherwise).

- [ ] a score from 0 to 100 with the breakdown kept visible
- [x] engagement up to 30, consistency 20, giveaway and brand signal 20, location 15, audience size 15
