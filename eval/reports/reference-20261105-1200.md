### sh-02 run 2: How does the team match algorithm score a candidate?

Answer: In SynergyHack, the team match algorithm scores a candidate using a gap-coverage score (`gapCoverage`) calculated via a Neo4j Cypher query:

1. **Collect Team Skills:** It finds the team's existing skills (`teamSkills`) by traversing from the team to its members via `MEMBER_OF` and to their skills via `HAS_SKILL` (`(t:Team)<-[:MEMBER_OF]-(m:User)-[:HAS_SKILL]->(ts:Skill)`).
2. **Find Eligible Candidate Skills:** It selects candidate users (`c:User`) who are not members of the team (`NOT (c)-[:MEMBER_OF]->(t)`) and identifies candidate skills (`cs:Skill`) that the team does not already possess (`NOT cs IN teamSkills`).
3. **Traverse Complements Edges:** From each eligible candidate skill, it traverses directed `COMPLEMENTS` edges `(cs)-[r:COMPLEMENTS]->(x:Skill)` to skills in `teamSkills` (`x IN teamSkills`).
4. **Sum Strengths:** The score (`gapCoverage`) is calculated by summing the `strength` property of the `COMPLEMENTS` edges for all of the candidate's new skills (`sum(coalesce(r.strength, 0))`).
5. **Filter Candidates:** Only candidates with a `gapCoverage > 0` are retained, sorted descending by `gapCoverage`, and returned (up to the requested limit).

- [x] it runs in Neo4j and only counts candidate skills the team does not already have
- [x] it sums the COMPLEMENTS strengths from those skills to the team's skills
- [ ] candidates with a score of zero are dropped and the top N (20 by default) are returned

### sh-07 run 1: How is rate limiting done per IP in synergyhack?

Answer: Rate limiting per IP in synergyhack is implemented by the `rateLimit` middleware function in `synergyhack/server/src/middleware/rateLimit.js` as follows:

1. It retrieves the IP address from `req.ip` (or defaults to `'unknown'`) and creates a Redis key in the format `ratelimit:${ip}`.
2. It increments the counter for that key using `client.incr(key)`.
3. If `count === 1`, it sets a key expiration using `client.expire(key, WINDOW)` where `WINDOW` is set to `1`.
4. If `count` exceeds `LIMIT` (where `LIMIT` is set to `60`), it returns a `429` status code with JSON `{ error: 'Too many requests' }`.
5. If `count` is within the limit, it proceeds by calling `next()`.
6. If an error occurs during the process, it fails open by calling `next()`.

- [x] Redis INCR on a key per IP
- [x] EXPIRE set when the count is 1
- [x] limit of 60 per window
- [x] returns 429 Too many requests

### fs-01 run 3: How is the fit score of a streamer computed and what are its parts?

Answer: The fit score of a streamer is computed by the function `fit_score(r, sweep_days)` in `fracton-scanner/streamer_finder_v3.py`. It returns a total score from 0 to 100 calculated by summing five components and rounding the result (`round(eng + consistency + signal + loc + size)`), along with a formatted breakdown string.

Its five components are:
1. **Engagement (`eng`, up to 30 points):** `min(r["engagement_pct"] / 10, 1) * 30` (10%+ engagement earns full marks).
2. **Consistency (`consistency`, up to 20 points):** `min(r["days_seen_live"] / max(sweep_days, 1), 1) * 20`.
3. **Giveaway and brand signal (`signal`, up to 20 points):**
   - `20` if `r["does_giveaways"]` is true and either `r["has_sponsor_signal"]` or `r["brand_count"]` is true
   - `15` if `r["does_giveaways"]` is true
   - `10` if `r["has_sponsor_signal"]` or `r["brand_count"]` is true
   - `0` otherwise
4. **Location confidence (`loc`, up to 15 points):** Looked up from `r["location_confidence"]`:
   - `"high"`: 15
   - `"medium"`: 11
   - `"low"`: 6
   - `"none"`: 0
5. **Audience size (`size`, up to 15 points):** Based on `v = r["avg_viewers"]`:
   - `15` if `20 <= v <= 80`
   - `10` if `VIEWERS_MIN <= v <= VIEWERS_MAX`
   - `3` otherwise

- [x] the score is the rounded sum of five parts and is at most 100
- [x] engagement up to 30, consistency 20, giveaway and brand signal 20, location 15, audience size 15

### gh-06 run 1: How does the gateway decide which backend service to forward a request to, and what does it return when the resource is unknown or the service is down?

Answer: Based on code written by course template in `GameHub/services/gateway/app/main.py`:

1. **How the gateway decides which backend service to forward to:**
   - It splits the incoming `path` by `"/"` into `segments` (`segments = path.split("/")`). If `len(segments) < 2`, it returns a `Response(status_code=404, content="Not found")`.
   - It extracts the resource name from `segments[1]`.
   - It looks up `segments[1]` in the `ROUTES` dictionary (`target_base = ROUTES.get(resource)`), which maps resource names (such as `"users"`, `"games"`, and `"activities"`) to backend service URLs defined in `settings`.
   - If a target base URL is found, it constructs `target_url = f"{target_base}/{path}"` and forwards the request using an `httpx.AsyncClient` request with a timeout of 10.0 seconds.

2. **What it returns when the resource is unknown:**
   - If `target_base` is `None`, it returns a `Response(status_code=404, content=f"Unknown resource: {resource}")`.

3. **What it returns when the service is down:**
   - If an `httpx.RequestError` exception is raised when trying to forward the request, it catches the exception and returns a `Response(status_code=503, content="Service unavailable")`.

- [x] ROUTES maps users, games and activities to service URLs
- [x] the resource name is read from the URL path, for example /users/...
- [x] 404 for an unknown resource
- [x] 503 when the service cannot be reached
- [x] course template
