### sh-02 run 2: How does the team match algorithm score a candidate?

Answer: The team match algorithm (implemented in `findMatches` in `server/src/services/match.service.js` and described in Neo4j documentation and report) scores a candidate using a gap-coverage score (`gapCoverage`) through the following steps:

1. **Collect Team Skills**: It traverses from the `Team` node through its members (`:MEMBER_OF`) to their skills (`:HAS_SKILL`) to collect a distinct set of existing team skills (`teamSkills`).
2. **Identify Candidate Skills**: It finds candidate users (`User`) who are not members of the team and who possess skills (`cs:Skill`) that are not already present in `teamSkills`.
3. **Traverse Complementary Relationships**: For each eligible candidate skill, an `OPTIONAL MATCH` follows directed `:COMPLEMENTS` edges (`[r:COMPLEMENTS]`) from the candidate's skill to any team skill in `teamSkills`.
4. **Calculate Gap Coverage Score**: The score (`gapCoverage`) is calculated by summing the edge strengths: `sum(coalesce(r.strength, 0))`. If a candidate skill does not complement a team skill, `coalesce` evaluates to 0.
5. **Filter and Rank**: Candidates are filtered to keep only those with `gapCoverage > 0`, and candidates are ordered by `gapCoverage DESC` (limited to `limit`, which defaults to 20).

- [x] it runs in Neo4j and only counts candidate skills the team does not already have
- [x] it sums the COMPLEMENTS strengths from those skills to the team's skills
- [x] candidates with a score of zero are dropped and the top N (20 by default) are returned

### sh-07 run 2: How is rate limiting done per IP in synergyhack?

1. It gets the IP from `req.ip || 'unknown'` and forms a Redis key named `ratelimit:${ip}`.
2. It increments the counter for that key using `await client.incr(key)` (imported from `../db/redis`).
3. If `count === 1`, it sets an expiration on the key using `await client.expire(key, WINDOW)`, where `WINDOW` is defined as `1`.

5. Otherwise, it calls `next()` to continue.
6. If an error is thrown in the `try` block, it fails open by catching the error and calling `next()`.

### fs-01 run 3: How is the fit score of a streamer computed and what are its parts?

Answer: The fit score of a streamer is computed by the `fit_score(r, sweep_days)` function on a 0–100 scale, calculated as `round(eng + consistency + signal + loc + size)`. It returns the rounded total score along with a breakdown string.

Its parts and scoring logic are:
1. **Engagement (`eng`, up to 30 points)**: `min(r["engagement_pct"] / 10, 1) * 30` (10%+ engagement gets full marks).
2. **Consistency (`consistency`, up to 20 points)**: `min(r["days_seen_live"] / max(sweep_days, 1), 1) * 20`.
3. **Giveaway + Brand Signal (`signal`, up to 20 points)**:
   - `20` if `r["does_giveaways"]` and either `r["has_sponsor_signal"]` or `r["brand_count"]` is true/non-zero.
   - `15` if `r["does_giveaways"]` only.
   - `10` if `r["has_sponsor_signal"]` or `r["brand_count"]` only.
   - `0` otherwise.
4. **Location Confidence (`loc`, up to 15 points)** based on `r["location_confidence"]`:
   - `"high"`: 15
   - `"medium"`: 11
   - `"low"`: 6
   - `"none"`: 0
5. **Audience Size (`size`, up to 15 points)** based on `v = r["avg_viewers"]`:
   - `15` if `20 <= v <= 80`
   - `10` if `VIEWERS_MIN <= v <= VIEWERS_MAX`
   - `3` otherwise.

- [x] the score is the rounded sum of five parts and is at most 100
- [x] engagement up to 30, consistency 20, giveaway and brand signal 20, location 15, audience size 15

### gh-06 run 1: How does the gateway decide which backend service to forward a request to, and what does it return when the resource is unknown or the service is down?

Answer: Based on `GameHub/services/gateway/app/main.py` (written by course template):

1. **How the gateway decides which backend service to forward a request to:**
   - In the `proxy` function, the gateway parses the resource name by splitting `path` by `"/"` (`segments = path.split("/")`).
   - If `len(segments) < 2`, it returns `Response(status_code=404, content="Not found")`.
   - Otherwise, it gets the resource name from `resource = segments[1]` and looks up `target_base = ROUTES.get(resource)`. The `ROUTES` dictionary maps resource names to service configuration settings (`"users"` to `settings.user_service_url`, `"games"` to `settings.game_service_url`, and `"activities"` to `settings.activity_service_url`).
   - If a target service base URL is found, it constructs `target_url = f"{target_base}/{path}"` and forwards the request using an `httpx.AsyncClient` with `timeout=10.0`.

2. **What it returns when the resource is unknown:**
   - If `target_base is None`, it returns a `Response` with `status_code=404` and `content=f"Unknown resource: {resource}"`.

3. **What it returns when the service is down:**
   - When an `httpx.RequestError` exception is raised during the forwarded request, it catches the exception and returns a `Response` with `status_code=503` and `content="Service unavailable"`.

- [x] ROUTES maps users, games and activities to service URLs
- [x] the resource name is read from the URL path, for example /users/...
- [x] 404 for an unknown resource
- [x] 503 when the service cannot be reached
- [x] course template
